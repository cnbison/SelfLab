## 设计权衡

### 1. critic 字段语义：`type` vs `event_type`

actor / experience 都用 `'event_type'` 键，但 critic.py 内部用 `event.get('type', 'neutral')`（早期 API 沿用）。**未统一**——本次保持现状 + 测试用 `'type'` 适配，避免破坏 runtime 已稳定运行 1000+ epoch 的 critic 链路。后续 Phase 3.3 PoC 时再做字段统一（见 [ARCH §3.3 Critic 字段规范](../ARCH.md) 待修订）。

### 2. MagicMock vs stub_llm fixture

real_critic_sense / real_encode_experience 测试不能用 `stub_llm` fixture（fixture 用 `side_effect=fake_chat_json` 返回 deterministic 值，无法覆盖"LLM 返回 None 时回退 stub"等关键路径）。

**决策**：real_* 类测试用 fresh `MagicMock()` 实例，自行控制 `return_value` / `side_effect`。stub_llm fixture 仅供 orchestrator / TwinSession 集成测试使用。

### 3. v5 真实 identity 聚类验证（公式 A3）

为防止 metrics.py 公式 A3 退化为字符串 unique（公式 A2），新增 `test_compute_self_entropy_v5_real_identities_clusters_low_h` —— 用 M2.2 v5 实验的 12 个真实 identity 字符串，验证：

- 公式 A2 → H ≈ 0.5+（每条字符串 unique）
- 公式 A3 → H < 0.5（"探索者" / "创造探索者" 等被识别为同一 cluster）

此测试是公式 A3 修复 P0-4 非单调问题（[M22_V5_REPORT.md 2026-07-10 重写版 §5.3](../experiments/M22_V5_REPORT.md)）的回归保护。
