## 背景与动机

- Day 3 落地的 TwinStateDB 是底层 API（手动 save/load），应用层用起来繁琐
- Day 4 把 TwinStateDB 与 SGEOrchestrator 集成：跑 N epoch 时自动触发 checkpoint，Phase Transition / Identity Crystallize / Narrative Build 触发额外 checkpoint
- 同时 migration 框架从占位升级为真实执行（DDL），让未来 schema 演进有路径
- 文档示例让 Phase 3.3 PoC（student-digital-twin）可直接 import + 跑

## 4 个关键设计决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | SGEOrchestrator 集成模式 | **db 外部传入 + lazy create_student** | 避免 orchestrator 创建/关闭 DB（生命周期冲突）；create_student 显式避免静默 INSERT 违反 R10 |
| 2 | checkpoint 触发器 | **多触发点 + 多次 save** | auto_N（每 100 epoch）+ phase_xition + identity_crystallize + narrative_build + session_end（手动）每次独立事务，保证 checkpoint history 完整 |
| 3 | 持久化失败处理 | **不中断 epoch 循环 + stderr 记录** | 应用层决定是否 fatal；实验场景下 DB 失败不应让 LLM 调用浪费 |
| 4 | Migration 框架 | **注册表 + 幂等性 + 失败回滚** | 新迁移函数只需加一行注册；PRAGMA table_info 检查列避免重复 ALTER；DDL 失败抛 MigrationError 不污染 DB |

## 实施过程的关键修复

1. **MemoryCrystallizer.__len__ 导致 truthiness=False**（Day 3 commit 2 遗留）：
   - snapshot_all 中 `self.crystallizer.snapshot() if self.crystallizer else None` 走 else 分支
   - 改用 `is not None` 替代 truthy 判断
   - 这是 Day 3 17/17 测试没暴露的隐性 bug（snapshot_all 内部 dict 字面量 evaluate 时 self.crystallizer 是 MemoryCrystallizer 实例，但 `if self.crystallizer` evaluate 为 False）

2. **checkpoint history ORDER BY**：
   - 默认 `ORDER BY epoch DESC, saved_at DESC`（最新在前）
   - 测试断言时用 sorted() 比较，不依赖顺序

3. **Schema_version 客户端/DB 兼容性**：
   - 迁移流程：先以源版本打开 + migrate_schema(target) → 关闭 → 再以目标版本打开
   - 客户端版本与 DB schema_meta 不一致时抛 SchemaVersionError（_validate_schema_version）

4. **Migration 幂等性**：
   - PRAGMA table_info(students) 检查列是否存在
   - CREATE INDEX IF NOT EXISTS（SQLite 原生支持）
   - 连续调用 2 次无副作用
