## 讨论主题

TwinSession 让"加载 + 重建 orchestrator"变得透明，但 Orchestrator 内部 Critic/Actor LLM prompt 只看 signals + values + drives——看不到 App 层领域信息（学生姓名/年级/学科 mastery）。SGE 永远是"通用 AI 婴儿"，不知道"这是 Alice 的数字孪生"。

Day 5 落 SSOT 03-context-injection.md 的 plumbing 部分：
- TwinContextBuilder（薄壳拼装器）
- AppContext（typed 契约，Phase 3.3 PoC 用）
- critic / actor / orchestrator / session 全链路透传

## 关键设计决策

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 范围 | **plumbing-only** | SSOT 假设 MasteryState/StudentEvent 已实现，但这些是 Phase 3.3 范畴。落 plumbing 让 Phase 3.3 直接消费 builder 接口，类型到时补 |
| 2 | mastery_state 接入 | **duck typing** | `summary() / most_recent_struggling() / learning_velocity()` 三方法鸭子调用；缺失/异常静默回退 |
| 3 | extra_context 行为 | **完全覆盖默认 8D** | App 层权威；保留 App 私有字段（student_name 等）原样 |
| 4 | 错误降级 | **mastery 异常不污染 ctx** | 单元测试明示：duck 调用抛 RuntimeError 不应让 critic 拿到 None 字段 |
| 5 | stub 数值扰动 | **仅 8D 数值字段加噪** | 早期 bug：原 stub 对所有字段加噪导致 `string + float` 报错。修复：加 isinstance(int, float) 守卫 |

## 实施过程的 2 个 bug

1. **stub_critic_sense 加噪炸了 App 字符串**

   早期测试 8 抛 `TypeError: can only concatenate str (not "float") to str`。原 stub 对 context 里**所有字段**加 Gaussian 扰动，没区分 8D 数值 vs App 字符串。`student_name` 是 `'Alice'`，加 float 必炸。

   修复：扰动循环改用 `if isinstance(context[field], (int, float)): continue`。这个修复同时也让 App 私有字段（整数/字符串）原样保留。

2. **to_dict 测试断言反了**

   `assert 'learning_pace' not in d` 本意是检查 extra 不被包成嵌套 dict，但我的实现是平铺合并（design 正确），所以 learning_pace 应该在 d 顶层。修正断言为 `assert 'extra' not in d`（断言 extra 字段被消费）。
