## 设计权衡

### 1. Shim 模式 vs 完全移除 inline runner

采用 **shim 模式**：保留 `_run_*_unit_tests()` 函数名 + `if __name__ == "__main__":` 入口，内部改为 thin subprocess 调用 pytest。

**好处**：
- `python -m sge.actor` / `python -m sge.persistence` 等历史用法仍工作
- pytest 自动发现 `tests/unit/test_*.py`，IDE/CI 直接用
- 未来 100% 移除 inline 时只需删除 shim 一处

### 2. Fixture 选择

- `tmp_db_path`：用 `tempfile.mkstemp` 而非 `tmp_path`（pytest 内置）—— TwinStateDB 接受 str 路径且需要显式清理
- `stub_llm`：用 `unittest.mock.MagicMock` 而非真实 SGELLMClient —— 单元测试不应触发真实 LLM 调用
- `_reset_session_registry` 用 autouse —— 防止 session.py 测试污染全局 registry

### 3. 覆盖率目标的取舍

ROADMAP 退出标准是"10 个模块平均 ≥ 80%"。本次仅完成 5 个：

- **达标的 3 个**：persistence 89% / context_injection 86% / event 已 81%（注：event 不在第一批但已有部分覆盖）
- **接近 80% 的 2 个**：baseline 79% / orchestrator 76% / actor 73%

未达 80% 的原因主要是 **LLM 实时路径未覆盖**（actor.real_actor_express / orchestrator 的 phase transition 触发条件）—— 这些需要真实 LLM 或 mock 完整链路，留第二批处理。
